# 5h 双限额与纯周额度怎样一起用

`balanced_priority_policy: capacity_deadline` 只在均衡模式生效。目标按顺序是：让真实请求完成；减少自然重置前来不及用的量；在前两者接近时保留能接突发流量的纯周额度、避免会话反复换号。没有未来流量、未来实际重置时间和下个请求大小的先验信息，不存在对所有轨迹都最优的在线策略。

**同一单位，两项限制。** 用容量估计把百分比换成工作量。双限额号周余量为 W、本轮 5h 余量为 H，现在最多只能用 min(W,H)；纯周号现在能用 W。这里已经扣除了周保留量、在途预留和待上游确认的已完成消耗。按套餐估计的绝对容量仍是估计。不给未来补量、公告、时间经过或持有的卡记余额。

**先用会错过的 5h 窗口。** 对一个已启动的 5h 周期，r 是其真实下次重置，D 是规划截止，F 是完整一轮 5h 的容量。若 r < D，之后最多还有 N = ceil((D-r)/5h) 轮；恰在 D 的补量属于下一阶段。本轮至少有 L = min(H, max(0,W-N×F)) 是错过以后连理想条件下都补不回的。若 L 连本次请求都容不下，不把它列为抢跑理由。多个必要窗口先按最早重置分组，再按需要用的量分配。移动的满额占位时间不能提供这种优先权。

**纯周何时上场。** 在自然补耗窗口外，有可用双限额号就先用它。按生产的 48h/24h/15% 为例，在两段之间逐步提高纯周账号的合计目标上限；同批只有一个自然重置期限时，48h 为 0、36h 为 7.5%、24h 前接近 15%。最后 24h 切为按真实自然期限、剩余量与近期已分配工作调度，不再受 15% 限制。唯一让必要 5h 窗口插队的条件：每一个可用的临期纯周号在最近两个不重叠的 5 分钟内都有原生消耗证据；取较低的实测速度再减半，在较早 5h 重置后，最多外推一小时，也仍有望用完这个号的余额并多容纳一个请求。没有证据就优先纯周。这个判断是保守估计，不是对未来流量的保证。

**集体重置分为预告与事实。** 可填 `collective_reset_window: "最早RFC3339时间/最晚RFC3339时间"`，不确定或只有事后公告则留空。两端须含时区，最长相隔 24h；精确时刻可写相同的两端。提前按最早可能时间保护必要的 5h 轮次，进入最早时间前一轮 5h 后启动冲刺。如果预告会在下次 5h 之前兑现，这一单用哪种号都计入当前活动；同时防备预告落空、下个真实 5h 窗口内又来高峰：先用超过下一整轮仍无法补上的双限额余量。其余按本轮真正能用的量分配，不拿双限额号的完整周余量跟纯周号比。在最晚时间到达、或上游多账号达到现有重置确认条件后结束预告调度。单号已核实的重置只撤下该号的活动优先权。没有社交媒体订阅，不会猜测下次活动时间。

**一张重置卡只是一次选择。** 手动卡可恢复该号两种额度，派单器没有兑卡操作。仅对已经开启到期自动用卡、原生卡列表新鲜完整、账号身份相同、第一张未过期卡适用且该凭证已用过额度的情形，才把现有计划的用卡时间作为软截止。在计划前最后一轮 5h 可提前消耗该号现有额度；其他号不继承它的卡。兑卡、复查及重复使用保护仍由原来的独立流程负责。

**缓存与回退。** 保持可用热会话及宿主绑定的 WebSocket。在直接绑定的会话超过两段缓存期、没有原请求在途、目标能预留整单且有并发位时才主动迁移。迁入可用临期纯周号后不因旧号 5h 恢复而跳回；账号不可用、达到保留线或相关冲刺结束才重新比较。额度不足走现有回退或等待，不用新请求制造消耗。候选标签说明账号性质，实际请求的理由在 ADQ 最近一次决策中可查。

**复验。** `go test -v -run '^TestCapacity(Mixed|Natural|Soft|Earlier|Tranche)' .`。混合池试验让实际选择器逐单处理请求，独立的动态规划枚举每个时段所有可行分配给出离线上限。其假设为等成本请求、已知测试容量、一双限额加一纯周号；它不证明真实多账号和长会话下的全局最优。
