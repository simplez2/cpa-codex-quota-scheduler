# Codex 额度调度

源码版本：**0.3.32**。

CPA 原生插件，提供额度调度、会话粘性、凭据并发限制、额度恢复等待和管理面板。
使用 CPA 的原生账号清单与额度查询，不需要 Keeper、独立数据库或额外账号服务。

## 调度规则

1. 新会话优先使用仍有可用 **5h 额度**的凭据，再考虑已确认只报告周额度的备用凭据。
2. 同类额度中，**官方已确认的重置时间越近，优先级越高**，尽量在自然重置前使用余量。
3. 同一优先组内再执行均衡、周预算和请求预约。并发限制、真实额度上限和冷却继续有效。
4. 已绑定且可用的会话保持粘性，避免同一会话因排序波动频繁切换凭据。
5. 官方剩余重置次数、本地观察到的周期次数分别展示；查询缺失表示未知，明确返回 0 才是没有。
   仅有周额度的部分响应不等于确认没有 5h 限制；重置时间经过也不等于已经补满。

| 模式 | 用途 |
| --- | --- |
| 均衡并发 `balanced` | 多个会话使用符合优先级和准入要求的凭据，保留各会话的绑定关系。 |
| 串行调配 `serial` | 优先使用当前凭据，在限制或策略触发时交接；默认模式。 |
| 传统调度 `legacy` | 保留旧选择器；仍受共同额度优先级和安全条件约束。 |
| 观察对比 `shadow` | 观察预算判断；不代表可绕过真实额度和冷却。 |
| 动态节奏控制 `enforce` | 根据预算和预约约束控制使用节奏；需要准确额度观测。 |

这些模式不能增加上游额度。日预算是“剩余额度 ÷ 距周重置的剩余时间”的使用速度，
不是提供商额外发放的日额度。突发全体重置只有得到新的官方观测后才成为调度证据。

## 面板与权限

在 CPA 管理中心打开 **插件 → Codex 额度调度**。面板可以查看额度、缓存新鲜度、
官方重置次数、实际在途并发，以及修改调配和预热设置。刷新面板读取缓存，不自动消耗模型额度。
预热默认关闭，启用后会消耗实际额度。

插件是载入 CPA 进程的原生动态库，能力声明不构成沙箱。它需要 CPA 管理密钥；
该密钥没有插件专用的端点权限范围，应通过只读文件提供，并限制 CPA 进程和状态目录权限。
到期诊断会通过 `host.auth.get` 读取凭据 JSON。`auth_expiry_auto_repair` 默认开启，
只在严格验证后移除不透明 PAT 的陈旧顶层到期字段；关闭后不写回，但仍读取诊断。
OAuth/JWT 到期不改写。详见 [CPA_PERMISSIONS.md](CPA_PERMISSIONS.md)。

## 兼容与验证

- 凭据并发保护需要 CPA v8.0.4+ 的请求 ID 与终态回调；旧宿主需要关闭该项。
- 长时间自动等待需要匹配版本的宿主补丁。安装插件本身不会给原版 CPA 增加此能力。
- v8.0.44 宿主见 [集成说明](integration/CONTINUITY-v8.0.44.md)；旧版本补丁不能混用。
- Linux 包使用 Debian 12 glibc 基线；另外提供 Linux ARM64、macOS Apple Silicon 和 Windows x64。
- CI 对 Linux、Windows、macOS 执行测试、竞态检查、静态检查、漏洞扫描和动态库构建。
  本地故障注入覆盖恢复、取消、超时、WebSocket、反风暴和 5h 优先级；它不等同于生产账号耗尽验收。

每个安装包包含授权和权限说明，并记录动态库指纹、平台、工具链和源码提交。
发布前核对全部四个包，发布后可用 `checksums.txt` 检查下载是否完整。
哈希校验不构成独立签名。详细使用和配置说明见 [README.md](README.md)。
